Python / Codex

完全不會寫程式，可以用 Codex 學 Python 嗎？

可以，但方法很重要。Codex 最適合當作學習助教，幫你拆任務、解釋程式、修正錯誤，而不是直接替你完成所有作業。

先從很小的任務開始

初學者不要一開始就做大型專案。比較好的第一步，是請 Codex 幫你做一個 20 行以內的小程式，例如自我介紹產生器、猜數字遊戲、待辦事項清單或 CSV 成績統計。

任務越小，你越能看懂每一行程式，也比較容易知道錯在哪裡。

不要只貼「幫我寫」

比較好的 prompt 是：「請先解釋需求，列出步驟，再產生一版短小的 Python 程式。每一段都用初學者聽得懂的方式說明。」這樣你拿到的不只是程式碼，也拿到學習脈絡。

一定要自己執行

學程式不能只看結果。你需要把程式貼到本機執行，觀察輸出，故意改幾個地方，看看錯誤訊息怎麼變。錯誤訊息其實是最好的教材，因為它會告訴你電腦在哪裡看不懂。

建議的學習循環

  1. 描述一個很小的任務。
  2. 請 Codex 拆步驟，不要直接做大專案。
  3. 執行程式，確認輸出。
  4. 請 Codex 解釋每一行。
  5. 自己改一個小功能，再請 Codex 檢查。

這個循環比一次產生完整專案慢一點，但比較能真的學會。

動手練習：三筆支出的加總

先不用檔案、網路或額外套件，只處理固定資料。目標是輸入三筆支出 35、60、25，得到合計 120。先手算答案，再用程式核對，才能分辨程式正確與看起來合理。

expenses = [35, 60, 25]
total = sum(expenses)
print(f"合計：{total} 元")

把程式存成 expenses.py，在有 Python 3 的環境執行 python expenses.py；部分系統使用 python3 expenses.py。範例不會寫入檔案。預期顯示「合計：120 元」。若找不到檔案，先檢查終端機目前的資料夾與檔名。

把要求寫成可檢查的任務

我正在學 Python。請解釋這三行程式的資料如何流動，再教我加入一筆 40 元的支出。請先讓我預測結果，不要直接提供整個新專案，也不要替我安裝套件。

新增 40 後應得到 160。用空清單測試，合計應為 0；用 [0, 10] 測試，應為 10。把數字改成字串 "35"，觀察型別錯誤，先理解輸入資料，再討論轉換。

完成檢查與延伸

  • 能解釋清單、sum 與變數 total 的用途。
  • 能在執行前預測增加或移除資料後的結果。
  • 能保存實際輸出，指出測過與尚未測過的情況。

下一步才加入類別或讀取 CSV。使用自己製作的假資料練習。可搭配《Codex CLI 入門》介紹了解完整專案練習所需的先備能力。
