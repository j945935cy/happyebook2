2. 看這一章要學什麼

4. 檢查 Codex 做出的結果
5. 再提出一個小修改任務

這本書的重點不是背語法，而是學會把需求說清楚，讓 Codex 幫你完成小步驟，然後用檢查清單確認結果。

## 第 1 章：如何請 Codex 做小作品

### 1.1 先把任務縮小

初學者最容易犯的錯，是一開始就要求 Codex 做完整的大系統。例如「幫我做一個英文學習平台」太大，Codex 可能會一次改很多檔案，也比較難檢查。

比較好的方式是把任務縮小：

```text
請修改一個指定檔案。
目標是新增一個小功能。
限制是不加後端、不引入框架。
完成後請檢查手機版、連結與主要操作流程。
```

小任務比較容易完成，也比較容易知道哪裡出錯。

### 1.2 固定使用 prompt 骨架

每次請 Codex 做事，都可以使用下面這個格式：

```text
請修改 [檔案或目錄]。
目標：[一句話說明要完成什麼]
限制：使用 HTML/CSS/Vanilla JavaScript，不加後端，不引入框架。
功能：
1. [功能一]
2. [功能二]
3. [功能三]
完成後請檢查：手機版、JavaScript 語法、本機連結、主要操作流程。
```

這個格式有四個好處：

- Codex 知道要改哪裡。
- Codex 知道不要加入太重的工具。
- 你比較容易檢查結果。
- 出錯時比較容易請 Codex 修正。

### 1.3 做完後一定要檢查

Codex 回覆「完成」不代表作品真的完成。你要自己確認：

- 頁面能不能打開
- 手機版有沒有文字重疊
- 按鈕能不能按
- 圖片有沒有破圖
- 連結有沒有失效
- JavaScript 有沒有語法錯誤

如果檢查到問題，不要直接叫 Codex「全部重做」。比較好的說法是：

```text
剛才的修改有一個問題：[具體描述問題]。
請只修正這個問題，不要重構其他部分。
完成後請再檢查 [指定項目]。
```

## 第 2 章：作品 1：Leo 的學校一天

### 2.1 作品目標

「Leo 的學校一天」是一頁中英對照童書。每一頁包含英文句子、繁體中文翻譯、朗讀提示、單字列表與簡單插圖。

這個作品適合當第一個練習，因為它是靜態 HTML 頁面，不需要後端，也不需要複雜互動。你可以先練習請 Codex 新增或修改一頁內容。

### 2.2 你會學到什麼

完成這個練習後，你會學到：

- 如何請 Codex 修改指定 HTML 檔案
- 如何沿用既有的頁卡結構
- 如何新增中英對照內容
- 如何保持 SVG 插圖、文字與單字提示一致
- 如何檢查手機版排版是否正常

### 2.3 先觀察原本的頁面

原本的頁面檔案位置：

```text
mini-projects/school-day-picture-book/index.html
```

線上作品：https://happyebook.com/mini-projects/school-day-picture-book/

觀察時先看三件事：

1. 每一頁都使用 `page-card` 結構。
2. 插圖放在 `art-frame` 裡面。
3. 文字區塊包含英文、中文、朗讀提示與單字列表。

你不需要一開始就看懂每一行 SVG，只要知道新頁要放進相同結構裡。

### 2.4 第一次給 Codex 的 prompt

把下面這段 prompt 給 Codex：

```text
請修改 mini-projects/school-day-picture-book/index.html。
目標：在「Leo 的學校一天」最後新增第 9 頁。
內容：
- 英文句子：Leo packs his school bag for tomorrow.
- 繁中翻譯：Leo 整理明天要用的書包。
- 朗讀提示：packs 是「整理、打包」；tomorrow 是「明天」。
- 單字 chips：pack、school bag、tomorrow
- 新增一張簡單 SVG 插圖，畫面是 Leo 把書放進書包。
限制：
- 使用現有 page-card 結構。
- 不引入外部圖片、框架或後端。
- 保持手機版可讀，不要讓文字或插圖溢出。
完成後請檢查 JavaScript 語法、手機版版面和本機連結。
```

### 2.5 Codex 可能會做什麼

Codex 通常會在最後一個 `page-card` 後面新增一組新的 `article`，並放入：

- 新的 SVG 插圖
- 頁碼 9
- 英文句子
- 中文翻譯
- 朗讀提示
- 三個單字項目

如果 Codex 做得太複雜，例如加入外部圖片或新的函式庫，要請它改回簡單靜態 HTML。

### 2.6 完成後怎麼檢查

打開頁面後，照下面順序檢查：

1. 頁面最後有第 9 頁。
2. 英文句子是 `Leo packs his school bag for tomorrow.`
3. 中文翻譯是「Leo 整理明天要用的書包。」
4. 朗讀提示有解釋 `packs` 和 `tomorrow`。
5. 單字列表有 `pack`、`school bag`、`tomorrow`。
6. 插圖內容和句子一致。
7. 手機版沒有文字重疊或橫向捲動。
8. 首頁與小作品頁連到這本童書的連結仍然正常。

### 2.7 如果結果不正確，怎麼請 Codex 修正

如果新增的第 9 頁文字太長，手機版跑版，可以這樣說：

```text
第 9 頁在手機版會水平溢出。
請只調整第 9 頁的版面或 CSS，讓文字和插圖在 390px 寬度內正常顯示。
不要修改其他頁內容。
```

如果插圖和內容不一致，可以這樣說：

```text
第 9 頁插圖沒有表現「整理書包」。
請只修改第 9 頁 SVG，畫面要有 Leo、書包和書本。
不要改英文句子與中文翻譯。
```

### 2.8 下一個小任務

完成第 9 頁後，可以再練習一個小修改：

```text
請在 Leo 的學校一天頁面底部新增「回到小作品列表」連結。
連結目標是 ../
保持現有網站風格，不要新增外部套件。
完成後請檢查連結可用、手機版不溢出。
```

這個任務可以練習頁面導覽，也能學會檢查相對路徑。

## 第 3 章：作品 2：Mia 在家的一天

### 3.1 作品目標

「Mia 在家的一天」是第二本中英對照童書。主角是 Leo 的 4 歲妹妹 Mia，內容從起床、早餐、玩積木、畫圖、午睡、喝茶、和 Leo 讀書，到晚上睡覺。

這個作品適合練習「修改既有頁面」。和第 2 章新增 Leo 的第 9 頁不同，這一章的任務是挑一頁改成新的生活情境。這樣可以練習不破壞整本書結構，只修改指定內容。

### 3.2 你會學到什麼

完成這個練習後，你會學到：

- 如何請 Codex 修改指定頁卡
- 如何讓英文句子符合 4 歲孩子的閱讀程度
- 如何同步修改英文、中文、朗讀提示與單字列表
- 如何檢查 SVG 插圖是否和新句子一致
- 如何限制 Codex 不要改到其他頁面

### 3.3 先觀察原本的頁面

原本的頁面檔案位置：

```text
mini-projects/little-sister-home-day/index.html
```

線上作品：https://happyebook.com/mini-projects/little-sister-home-day/

觀察時先看三件事：

1. 每一頁都使用 `page-card` 結構。
2. 文字區塊使用 `english`、`chinese`、`read-tip` 和 `word-list`。
3. 插圖放在 `art-frame` 裡，使用簡單 SVG。

這本書的讀者年紀比較小，所以英文句子要短，單字也要生活化。

### 3.4 第一次給 Codex 的 prompt

把下面這段 prompt 給 Codex：

```text
請修改 mini-projects/little-sister-home-day/index.html。
目標：把「Mia plays with blocks.」那一頁改成整理玩具的情境。
內容：
- 英文句子：Mia helps Mommy clean up toys.
- 繁中翻譯：Mia 幫媽媽一起收玩具。
- 朗讀提示：helps 是「幫忙」；clean up 是「整理、收拾」。
- 單字 chips：help、Mommy、clean up、toys
- SVG 插圖要改成 Mia 和媽媽一起把玩具放進籃子。
限制：
- 只修改這一頁，不要修改其他頁。
- 保持 4 歲孩子親子共讀的語氣。
- 不引入外部圖片、框架或後端。
- 手機版不能文字重疊或水平溢出。
完成後請檢查手機版版面、本機連結與主要內容是否一致。
```

### 3.5 Codex 可能會做什麼

Codex 可能會找到原本第三頁：

```text
Mia plays with blocks.
```

然後把英文、中文、朗讀提示、單字列表和 SVG 插圖一起改掉。

好的修改應該只影響這一頁。如果 Codex 改到封面、其他頁面或全站樣式，就要請它縮小修改範圍。

### 3.6 完成後怎麼檢查

打開頁面後，照下面順序檢查：

1. 原本玩積木那一頁已改成整理玩具。
2. 英文句子是 `Mia helps Mommy clean up toys.`
3. 中文翻譯是「Mia 幫媽媽一起收玩具。」
4. 朗讀提示有解釋 `helps` 和 `clean up`。
5. 單字列表有 `help`、`Mommy`、`clean up`、`toys`。
6. 插圖看得出 Mia、媽媽、玩具和收納籃。
7. 其他頁面內容沒有被改掉。
8. 手機版沒有文字重疊或橫向捲動。

### 3.7 如果結果不正確，怎麼請 Codex 修正

如果 Codex 改到太多頁，可以這樣說：

```text
剛才修改範圍太大。
請只保留「Mia helps Mommy clean up toys.」那一頁的修改，
其他頁面恢復原本內容。
不要重構整份 HTML。
```

如果英文太難，可以這樣說：

```text
這一頁的英文對 4 歲孩子太難。
請把英文句子維持在 6 個字左右，使用生活常見單字。
中文翻譯和朗讀提示也要一起更新。
```

如果插圖沒有表現整理玩具，可以這樣說：

```text
插圖還看不出「收玩具」。
請只修改這一頁 SVG，加入玩具籃、積木或小球，讓 Mia 和媽媽正在整理玩具。
不要改文字內容。
```

### 3.8 下一個小任務

完成這一頁後，可以再練習一個小修改：

```text
請在 Mia 在家的一天頁面新增一個「適合親子共讀」的小提示區塊。
位置放在封面介紹下方。
內容用 2 到 3 句繁體中文，提醒家長可以先唸英文，再用中文解釋。
保持現有網站風格，不引入外部套件。
完成後請檢查手機版不溢出。
```

這個任務可以練習新增說明區塊，也能學會控制文案不要太長。

## 第 4 章：作品 3：英文單字照打練習

### 4.1 作品目標

「英文單字照打練習」是一個簡單的 CAI 練習頁。畫面會顯示英文單字、中文解釋、使用方法與例句，使用者照著輸入單字，系統即時提示是否正確。

這個作品適合練習「修改 JavaScript 資料」。和前兩章的童書頁不同，這一章主要不是新增 HTML 區塊，而是找到資料陣列，加入新的單字資料。

### 4.2 你會學到什麼

完成這個練習後，你會學到：

- 如何請 Codex 找到資料陣列
- 如何新增結構一致的 JavaScript 物件
- 如何檢查畫面進度數字是否跟資料筆數一致
- 如何測試輸入正確與錯誤時的提示
- 如何避免只改畫面文字，卻沒有改到真正資料來源

### 4.3 先觀察原本的檔案

這個小作品有兩個重要檔案：

```text
mini-projects/english-cai/index.html
src/script.js
```

線上作品：https://happyebook.com/mini-projects/english-cai/

`index.html` 負責畫面結構，例如單字標題、輸入框、上一題、下一題和重新開始按鈕。

真正的單字資料放在 `src/script.js` 裡的 `practiceWords` 陣列。每一筆資料都有四個欄位：

```text
word
meaning
usage
example
```

所以這一章的任務，要請 Codex 修改 `src/script.js`，不要只改 HTML。

### 4.4 第一次給 Codex 的 prompt

把下面這段 prompt 給 Codex：

```text
請修改 src/script.js。
目標：在英文單字照打練習的 practiceWords 陣列新增 5 個單字。
新增單字：
1. create
2. project
3. simple
4. check
5. fix
每個單字都要包含：
- word
- meaning：繁體中文解釋
- usage：白話說明使用方式
- example：適合初學者的英文例句
限制：
- 只修改英文 CAI 使用的 practiceWords 陣列。
- 不改 HTML 結構。
- 不引入外部套件。
- 保持資料格式和原本 8 個單字一致。
完成後請檢查 JavaScript 語法、題數進度、輸入正確與錯誤提示。
```

### 4.5 Codex 可能會做什麼

Codex 應該會在 `practiceWords` 陣列最後新增 5 個物件。每個物件長得像這樣：

```text
{
  word: "create",
  meaning: "創造；建立",
  usage: "用來表示做出新的東西，例如建立檔案、作品或計畫。",
  example: "I create a small project with Codex."
}
```

如果 Codex 把資料加到 HTML 裡，這不是好的修改。因為畫面是由 JavaScript 讀取 `practiceWords` 後更新的，真正的資料來源在 `src/script.js`。

### 4.6 完成後怎麼檢查

打開英文單字照打練習後，照下面順序檢查：

1. 進度數字從原本 `1 / 8` 變成 `1 / 13`。
2. 按下一題可以看到新增的 5 個單字。
3. 每個新增單字都有中文解釋、使用方法與例句。
4. 輸入正確單字時，提示會顯示正確。
5. 輸入錯誤字母時，畫面會標示紅色字母。
6. 重新開始後會回到第一題。
7. JavaScript 語法檢查通過。
8. 手機版按鈕和輸入框沒有重疊。

### 4.7 如果結果不正確，怎麼請 Codex 修正

如果 Codex 只改了畫面預設文字，沒有改資料陣列，可以這樣說：

```text
剛才只改到 HTML 顯示文字，沒有改到真正的單字資料。
請改 src/script.js 裡的 practiceWords 陣列，
新增 create、project、simple、check、fix 這 5 筆資料。
不要修改 HTML 結構。
```

如果新增資料格式不一致，可以這樣說：

```text
新增的單字資料格式和原本 practiceWords 不一致。
請把每一筆都整理成 word、meaning、usage、example 四個欄位。
不要新增其他欄位，也不要改原本功能邏輯。
```

如果輸入功能壞掉，可以這樣說：

```text
新增單字後，照打輸入功能無法正常判斷。
請檢查 practiceWords 資料是否有語法錯誤，
並確認 renderWord 和 checkInput 可以正常讀取新增資料。
不要重寫整個練習程式。
```

### 4.8 下一個小任務

完成新增單字後，可以再練習一個小修改：

```text
請在英文單字照打練習加入「本題已嘗試次數」顯示。
位置放在答對數與正確率旁邊。
每次輸入非空內容時更新目前題目的嘗試次數。
限制：使用現有 attempts 陣列，不新增外部套件。
完成後請檢查重新開始會把嘗試次數歸零。
```

這個任務可以練習讀懂既有狀態資料，也能學會在不重寫程式的情況下加一個小功能。

## 第 5 章：作品 4：抽籤程式

### 5.1 作品目標

「抽籤程式」是一個純前端工具。使用者可以輸入候選名單，按下開始抽籤後，系統會隨機抽出一個結果，並把結果放進抽籤紀錄。

這個作品適合練習「在既有工具裡新增按鈕」。這一章的任務是新增「複製抽籤紀錄」功能，讓使用者可以把目前抽籤結果複製到剪貼簿。

### 5.2 你會學到什麼

完成這個練習後，你會學到：

- 如何請 Codex 修改單檔 HTML 小工具
- 如何新增一個按鈕並綁定事件
- 如何使用既有的 `history` 陣列
- 如何處理「有紀錄」和「沒有紀錄」兩種狀態
- 如何檢查剪貼簿功能是否可用

### 5.3 先觀察原本的檔案

這個小作品的檔案位置：

```text
mini-projects/lucky-draw/index.html
```

### 12.1 作品完成後，不要只看「能不能跑」

做完 2 本故事書與 8 個小遊戲後，第一件事不是急著發布，而是整理。整理的目的，是讓作品可以被別人打開、閱讀、操作，並且在手機和桌機上都不容易出錯。

對初學者來說，可以把完成品分成三層檢查：

1. 內容正確：文字、說明、規則和 prompt 沒有寫錯。
2. 操作正常：按鈕、輸入、遊戲流程、重設功能都能用。
3. 發布安全：路徑、連結、SEO、GitHub Pages 靜態部署都正常。

### 12.2 整理小作品首頁

當作品變多後，要讓讀者知道從哪裡開始。小作品首頁應該包含：

- 作品名稱
- 一句話說明
- 連結
- 適合練習的技能

可以給 Codex 這樣的 prompt：

```text
請修改 mini-projects/index.html。
目標：整理小作品列表，讓 2 本故事書與 8 個小遊戲容易閱讀。
需求：
1. 每個作品都要有名稱、簡短說明與連結。
2. 作品順序依照學習路線排列。
3. 不要放入「任務代理工具」作品。
4. 保持 Happy eBook 既有風格。
限制：
- 使用 HTML/CSS/Vanilla JavaScript。
- 不引入框架或外部套件。
- 保持手機版卡片不重疊。
完成後請檢查首頁、小作品頁、手機版與本機連結。
```

### 12.3 做全站連結檢查

小作品大多使用相對路徑。最常見的錯誤是：

- `../` 寫錯
- 圖片路徑失效
- 從子目錄回首頁失敗
- sitemap 沒加新頁

檢查時可以照這個清單：

```text
首頁可以連到小作品首頁。
小作品首頁可以連到每個作品。
每個作品可以回到小作品首頁。
每個作品的圖片、CSS、JS 沒有失效。
sitemap.xml 有新增主要作品網址。
手機版導覽列能打開與關閉。
```

如果請 Codex 幫忙，可以這樣說：

```text
請檢查本專案的本機 HTML 連結。
範圍：index.html、mini-projects/index.html、10 個小作品頁。
請找出 href 或 src 指向不存在檔案的地方。
不要修改檔案，先列出問題清單。
```

### 12.4 做功能檢查表

每個作品都要有自己的檢查項目。可以先用這張表：

| 作品 | 必查項目 |
| --- | --- |
| Leo 的學校一天 | 頁數、英文、中文、插圖、手機版 |
| Mia 在家的一天 | 句子難度、親子共讀語氣、插圖一致 |
| 英文單字照打練習 | 題數、輸入判斷、正確率、重新開始 |
| 抽籤程式 | 空名單、抽籤、移除已抽中、紀錄 |
| 賓果遊戲 | 抽號、標記、Bingo 判斷、重新開始 |
| 井字遊戲 | 輪流下棋、勝負、平手、計分 |
| 電子白板 | 粉筆、打字、復原、清除、下載 |
| 打磚塊雙人對戰 | 控制、得分、道具、重新開始 |
| 777 拉霸遊戲 | 分數規則、總分、最高分、無金錢功能 |
| 3D 摩天輪 | 旋轉、暫停、反向、速度、手機版 |

### 12.5 修正時，一次只修一件事

當你發現問題時，不要一次要求 Codex 重寫整個作品。比較好的方式是只描述一個問題。

範例：

```text
手機版 390px 寬度下，電子白板工具按鈕會換行不整齊。
請只調整工具列的 CSS，讓按鈕在手機版垂直排列。
不要修改 Canvas 繪圖邏輯。
```

這樣 Codex 比較不會改壞其他功能。

### 12.6 發布到 GitHub Pages 前的檢查

Happy eBook 是靜態網站，所以要確認作品不依賴後端。發布前檢查：

```text
沒有使用後端 API。
沒有需要 build step。
沒有 React、Vue、Next.js、Tailwind 或 Bootstrap。
沒有不穩定 CDN。
所有作品都能直接用 GitHub Pages 開啟。
相對路徑正確。
```

如果有使用 `localStorage`，也要確認：

```text
重新整理後資料仍存在。
重新開始按鈕不會誤刪不該刪的資料。
清除資料的按鈕有清楚文字。
```

### 12.7 最後總檢查

當 10 個作品都整理好後，可以請 Codex 幫你做最後總檢查。這次的目標不是新增功能，而是找出可能壞掉的地方。

可以使用這段 prompt：

```text
請檢查這個小作品網站。
範圍：首頁、小作品首頁、2 本故事書、8 個小遊戲。

請檢查：
1. 每個作品連結是否正常。
2. 每個作品是否能在手機版閱讀或操作。
3. 按鈕、輸入框、遊戲流程是否可用。
4. 是否有文字重疊、圖片破圖或 JavaScript 錯誤。
5. 是否有不適合公開的備註或草稿字樣。

請先列出問題清單，不要直接修改檔案。
```

### 12.8 完成本書後，你可以怎麼繼續

完成這 10 個作品後，你已經練過幾種常見的 AI coding 任務：

- 修改既有內容
- 新增一頁故事書
- 新增資料陣列
- 新增按鈕
- 新增遊戲狀態
- 新增 Canvas 工具模式
- 新增視覺主題
- 做手機版檢查

接下來可以自己設計第 11 個小作品。你可以先從這個 prompt 開始：

```text
我想新增一個純前端小作品。
目標：[寫一句話說明作品要做什麼]
限制：
- 使用 HTML、CSS、Vanilla JavaScript。
- 不使用後端。
- 不引入框架。
- 可以放在 GitHub Pages。
請先幫我拆成 3 到 5 個步驟，並列出每一步完成後怎麼檢查。
```

真正重要的不是一次做出很大的作品，而是能把任務拆小、讓 Codex 幫你完成一小步，然後自己檢查結果。這樣反覆練習，你會慢慢建立自己的 AI coding 工作流程。
